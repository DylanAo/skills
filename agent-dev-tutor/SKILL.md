# Agent 扩展开发入门课程

本技能是一份课程大纲与知识底稿，**不是讲授风格本身**。授课前先调用 `interactive-tutor` 技能，严格遵守其"讲一点 → 问一题 → 等回答 → 按反馈调整"的循环，再按本大纲逐课推进。

教学规则：
- 从学习者的已有知识出发，有基础可跳课；每课只展开当前一小步，配一个小检查。
- 优先用学习者自己的产品环境举例和实操；只讨论、不动手的要求应予尊重。
- 涉及具体产品的路径、字段、界面入口时，先核对官方文档，不凭记忆断言，不混用不同产品的规范。
- 课程核心视角反复使用：**每份文件先问"给谁看"——模型（大脑）、宿主（身体）、安装器还是人。**

## 第 1 课：Agent 与扩展总览

- Agent = 模型（负责想）+ 宿主（负责做：执行工具、读写文件、调度）+ 工具（手）+ 规则。
- 模型无法直接接触系统，真正执行命令的永远是宿主。
- 三大扩展分工：Skill 教方法（模型自觉）、Hook 做约束（机制强制）、MCP 扩展能力（造新工具）。
- 核心循环：模型决策 → 调工具 → 结果回上下文 → 再决策，直到完成。

## 第 2 课：Skill

- 本质：带 frontmatter 的 SKILL.md，写给模型看的岗位规程，不是代码。
- 三级加载：description 常驻用于触发决策 → 正文触发时加载 → 附件按需读。
- description 是触发器，写给决策中的模型，标准写法"是什么 + 何时用"。
- 主动调用（`/` 命令，确定性）与被动调用（模型判断，概率性）；关键操作用主动。
- 安装即放对目录（如 `~/.agents/skills/<name>/SKILL.md`），无注册表；界面导入与手动放置等价。

## 第 3 课：Hook

- 宿主在事件点直接执行的脚本，不经过模型，所以可靠。
- 常用事件：PreToolUse（执行前，可拦截）、PostToolUse（执行后，只能记录）、SessionStart、Stop。
- 三条通道：stdin 收 JSON（工具参数）→ 退出码裁决（0 放行、2 拦截）→ stderr 给模型解释原因。
- 打印"已拦截"没有强制力，拦截只能靠退出码；PostToolUse 无法挽回已执行的命令。
- 配置双入口：图形界面与 settings.json 手写的是同一份配置。
- 必备 shell 基础：stdin/stdout/stderr、`$?`、grep 命中返回 0、chmod +x。

## 第 4 课：MCP

- 开放协议，把能力做成独立服务，跨客户端复用；本地 stdio 与远程 url 两种接入。
- 工具三要素：name、description（模型使用依据）、inputSchema（参数定义）。
- FastMCP 写法：写 Python 函数 + @mcp.tool() 装饰器；函数名→name、docstring→description、类型注解→schema。
- 两份 JSON 分工：手写注册配置（宿主如何启动服务，写一次）与 SDK 自动生成的工具说明书（给模型看，无需手写）。
- 验证：连接器 ready + list_tools 能看到工具，只证明启动与 schema 加载，业务功能需单独实测。
- 架构价值：权限收窄——只给专用工具，好过给开放 shell。

## 第 5 课：子代理与自定义 Agent

- 核心价值：上下文隔离（过程留子代理、结论回主对话）与角色分工。
- 子代理看不到主对话历史，任务简报必须含：背景目标、已知线索（地址/凭据方式）、判断标准（阈值）、返回格式。
- 自定义 Agent 三字段：name、description（何时派遣）、instructions（独立上下文里的角色规程）。
- 硬保证层级：工具白名单/只读 MCP > Hook 拦截 > instructions 劝说。

## 第 6 课：插件打包

- 插件 = 把 Skill、MCP、Hook、Agent 等组件按规范打成可分发包，一次安装全部到位。
- manifest（如 .qoder-plugin/plugin.json）是装箱单：名称/版本/作者 + 组件路径指针，读者是安装器，不进模型上下文。
- 本地包走官方安装器导入：完成校验、登记来源/版本、写启用开关，才能被统一停用/卸载/更新。
- 跨产品原则：内容可移植（MCP 最通用、Skill 次之、Hook 配置需重写），包装不通用。

## 第 7 课：提示注入与独立 Agent

- 提示注入：指令与数据同通道，恶意网页/文件可劫持 agent 权限；不能指望模型自行分辨。
- 分层防御：权限最小化、Hook 硬红线、敏感操作人工审批、不可信内容交只读子代理隔离。
- 拦截规则要资产导向（枚举私钥、.env 等敏感文件），而非枚举攻击命令。
- 独立 Agent = 自己当宿主：审批逻辑、调用前后检查、上下文压缩都要自己实现，SDK 只帮扛通用部分。
- 架构原则：确定性任务归脚本（定时、阈值告警），非结构化判断归 agent（读日志、排障、写报告），混合使用。

## 建议实操作业（可选）

1. 写一个个人经验型 Skill（如网络诊断规程），验证主动/被动触发。
2. 写 PreToolUse 护栏拦截危险命令 + PostToolUse 命令日志，各测放行与拦截。
3. 用 FastMCP 写一个只读运维工具并注册，核对 list_tools 与 docstring 的对应关系。
4. 创建一个自定义巡检 Agent，用简报三要素（目标/线索/标准）派遣一次。
5. 把自己的 Skill 打成插件 zip，走安装器导入并观察注册信息。
